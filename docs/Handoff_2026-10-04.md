## 2. 本番反映の手順

1. **PR 作成 → レビュー → main へマージ**（まだ PR は作っていない）。
2. **VPS の SQLite ファイル（`DATABASE_URL` が指す `.db`）をコピーしてバックアップ**。
3. VPS で: `git pull` → `npm ci` → `npx prisma migrate deploy` → `npm run build` → standalone の静的ファイルコピー（`.next/static` → `.next/standalone/.next/static`、`public` → `.next/standalone/public`）→ `pm2 restart`。
4. 適用されるマイグレーション: `20261004012701_life_records`（追加のみ。DROP・テーブル再作成なし）。
5. Settings で Claude の API キーとモデルを設定（AI 財務を使う場合）。
6. 本番で通し確認（§4 のチェックリスト）。

> 注意: ユーザーがローカルで `npm run dev` を起動中のディレクトリで `npm ci` / `npm install` を実行すると dev サーバーが落ちる（10/2 に発生済み）。実行前に一声かけること。

## 3. データ移行の要点

- 既存 `Task.priority`（low/medium/high）→ 新 `Task.importance`（1/2/3）へマイグレーション内で自動コピー。`priority` 列は残してある。
- 既存タスクの `urgency` は null のまま。期限順リストに入り、マトリクス上は「未設定 n件」と出る。利用者がタスクを開いて設定する想定。
- Entry・Settings など既存テーブルは変更なし。既存データ入り DB でのマイグレーション適用と保持は検証済み。
- 新テーブル: `Hospital` / `HospitalVisit` / `WeightRecord` / `Memo` / `Tag` / `ShoppingItem` / `FinanceRecord`。

## 6. 知っておくべき設計上の注意

- 日時は必ず `lib/time/jst.ts` 経由で扱う。`new Date(y, m, d)` などのローカル時刻 API は使わない（VPS は UTC）。
- CSV 出力の URL に拡張子（`.csv`）を付けない。`proxy.ts` の matcher は拡張子付きパスを認証対象外にするため。Route Handler 側でもセッションを検証している。
- AI は下書きのみ。保存は利用者の確認後。AI 起点の記録は `source="ai"` と元入力 `sourceText` を残す。
- AI の構造化出力で enum を使わない（SDK の zod 変換が enum を強制しないため、一覧外の値で全体が失敗した。コード側で正規化する）。
- 病院を削除すると、その診察記録もすべて削除される（確認ダイアログあり。CSV で先に退避できる）。
- Memo / Hospital 等は Entry（不変の原情報）とは別の編集可能モデル（Task と同じ扱い）。
- 本ブランチで追加した依存: `@anthropic-ai/sdk`、`zod`。`next.config.ts` に Server Actions の body 上限 8MB を設定。
